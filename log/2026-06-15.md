## 遇到的问题与解决方案

- **问题 1：Claude API → DeepSeek API 格式迁移**
  - **描述**：最初计划使用 Claude API，实现后发现 API 格式复杂且用户提供的 key 是 DeepSeek。DeepSeek 使用 OpenAI 兼容的 Chat Completions 格式，与 Anthropic Messages 格式完全不同。
  - **解决**：重写了 `callClaude()` 为 `callDeepSeek()`。URL 改为 `https://api.deepseek.com/chat/completions`；Auth header 从 `x-api-key` 改为 `Authorization: Bearer`；请求 body 从 `{model, system, messages[{content:[{type,text}]}]}` 改为 `{model, messages[{role,content}]}`；响应解析从 `content[0].text` 改为 `choices[0].message.content`；Token 字段从 `input_tokens/output_tokens` 改为 `prompt_tokens/completion_tokens`。

- **问题 2：axios 15 秒全局限流超时导致 AI 分析失败**
  - **描述**：前端调用 AI 分析接口时报 `timeout of 15000ms exceeded`。全局 axios 实例统一设置了 15 秒超时，但 AI 分析需要 20-60 秒。
  - **解决**：`analysis.js` 中单独为 AI 接口设置 `timeout: 120000`（2 分钟）；后端 `RestClient` 同步设置 `connectTimeout(30s)` 和 `readTimeout(120s)`。前端全局超时不受影响。

- **问题 3：bash 终端 UTF-8 编码导致 curl 测试中文 JSON 报 500**
  - **描述**：Windows bash 下 curl 直接传中文 JSON 被 Jackson 解析为乱码（`Invalid UTF-8 start byte 0xb2`），误以为是后端 Bug。
  - **解决**：改用 Node.js `http.request` 进行测试，UTF-8 编码正确，所有 CRUD 接口正常。确认问题仅存在终端环境，浏览器/前端不受影响。
